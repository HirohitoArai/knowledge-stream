# プライバシーとデータの扱い — Knowledge Stream

最終更新: 2026-11-10（feature/full-prototype）

この文書は、Knowledge Stream プロトタイプが利用者のデータをどう扱うかを、利用者と運用者の両方に向けて明記するものです。アプリ内のプロフィールタブにも要約を表示しています。

## 利用者について保存するもの

### 端末の中だけに保存するもの（サーバーへ送らない）

LocalStorage の1キー（`knowledge-stream:client-state:v1`）にまとめて保存します。

| データ | 用途 |
| --- | --- |
| 視聴済み動画IDと視聴時刻 | 未視聴を優先するフィード並び順のため |
| 保存した動画ID | プロフィールタブの保存リストのため |
| 興味なし動画ID | フィードから除外するため |
| 選択中ジャンルID | 初回選択を省略し、フィード対象を決めるため |
| 匿名クライアントID（UUID） | 評価の重複防止のためだけに生成する無作為なID |
| 動画情報のキャッシュ | 保存リストのラベル表示のため |

- アカウント登録・ログインは利用者側にはありません。氏名・メールアドレス等は収集しません。
- プロフィールタブから、視聴履歴・保存・興味なし・すべて（ジャンル選択と匿名IDを含む）をいつでも削除できます。削除すると匿名IDは作り直されます。

### サーバーへ送るもの

| 場面 | 送る内容 | 保存先 |
| --- | --- | --- |
| 「役立った」「分類が違う」を押したとき | 動画ID、評価の種類、匿名クライアントID | D1 の `feedback` テーブル（下記のとおり変換して保存） |
| フィード・検索・ジャンル取得 | 選択中ジャンルID、検索文字列 | 保存しない（リクエスト処理のみ） |

- 匿名クライアントIDそのものは保存しません。サーバー側で HMAC-SHA-256（秘密鍵は Worker のシークレット `FEEDBACK_SECRET`）で変換した値だけを保存します。元のIDは復元できません。
- 同じ端末・同じ動画・同じ評価種類の重複は、データベースの一意制約で1件に制限します。
- サーバーに保存された評価は端末と結びつけられないため、利用者からの削除依頼に対応する手段はありません。プロフィールタブにもその旨を表示しています。
- フィードback の送信は頻度制限（同一匿名IDからのバースト抑制）をサーバー側で行います。

## 動画再生とYouTube

- 再生は公式 YouTube IFrame Player API を使います。動画本体を取得・保存・再配信することはありません。
- 再生に伴って YouTube（Google）と端末の間で通信が発生し、Google のプライバシーポリシーが適用されます。Knowledge Stream 側では再生履歴を YouTube から取得しません。

## 運用者（管理画面）について

- 管理画面 `/admin` と管理APIは Cloudflare Access で保護します。Access の認証情報（メールアドレス等）は Cloudflare 側で扱われ、このアプリのデータベースには保存しません。
- 管理APIは、Access の JWT 署名・対象（AUD）・発行者・有効期限をすべて検証し、失敗した場合は処理を行いません（fail-closed）。

## バックアップと保持

- D1 のデータ（登録動画・ジャンル・評価）は Git 管理しません。運用環境では Cloudflare D1 のエクスポート機能で定期的にバックアップし、マイグレーションは `migrations/` のファイルで管理します（適用済みマイグレーションは書き換えません）。
- ローカル開発用 seed（`seeds/`）は実環境へ適用しません。

## 未実装・注意
